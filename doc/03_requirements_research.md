# 需求调研记录

## 1. 调研目的

明确 DLT645 电表模拟器的核心使用场景、功能边界和当前实现缺口，为需求规格说明书和设计文档提供输入。

## 2. 调研来源

- 仓库已有说明文档
- 现有 Qt 工程源码结构
- 已实现界面和模块命名
- 当前数据库与日志实现逻辑

## 3. 当前识别出的用户诉求

| 编号 | 诉求 |
| --- | --- |
| R-01 | 支持创建连接并管理多个电表 |
| R-02 | 支持通过设备树浏览电表与数据分类 |
| R-03 | 支持编辑指定数据项 |
| R-04 | 支持随机化全部数据或当前分类数据 |
| R-05 | 总值与费率值、分相值之间需保持逻辑一致 |
| R-06 | 操作后要能保存，下次按表地址恢复 |
| R-07 | 操作成功后要在操作日志中可见 |
| R-08 | 支持导出当前数据列表 |
| R-09 | 支持通信调试和日志观察 |

## 4. 关键业务规则

- 电表地址是当前数据持久化的唯一识别键。
- 同一地址再次被读取时，应加载数据库中已有数据。
- 地址不存在时，应创建初始数据并首次入库。
- 数据随机化后，总电能、总需量、总功率等聚合值应与子项保持一致。
- 最大需量发生时间使用紧凑时间格式 `yyMMddHHmm`。

## 5. 当前实现中已体现的需求

- 连接管理
- 电表创建
- 设备树选择联动数据表
- 数据编辑、重置、随机化、导出
- SQLite 本地持久化
- 右侧操作日志显示

## 6. 待客户进一步确认的问题

- 最终需要完整覆盖哪些 DLT645 数据标识范围
- 是否需要多种冻结策略和历史结算日数据全部开放到 UI
- 是否需要密码权限控制的强校验
- 是否需要项目级保存/打开，而不只是表数据持久化
- 是否需要批量脚本导入、批量协议压力测试等高级能力

## 7. 调研结论

该项目的核心定位不是通用协议分析器，而是“可视化、可编辑、可恢复状态”的电表模拟工具。现阶段需求主线已经明确，后续应重点围绕协议完整性、数据一致性和持久化稳定性继续收敛。
