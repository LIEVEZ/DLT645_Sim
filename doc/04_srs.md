# 需求规格说明书（SRS）

## 1. 文档目的

定义 `DLT645_Sim` 的功能需求与非功能需求，作为开发、测试和验收基线。

## 2. 产品概述

`DLT645_Sim` 是一个基于 Qt5 的桌面应用，用于模拟支持 DLT645-2007 协议的电表设备，提供数据浏览、修改、随机化、持久化与通信调试能力。

## 3. 功能需求

### FR-01 连接管理

- 系统应支持创建串口连接。
- 系统应支持创建 TCP 连接。
- 系统应支持打开、关闭、编辑、删除连接。

### FR-02 电表管理

- 系统应支持在选定连接下创建电表。
- 系统应校验电表地址唯一性。
- 系统应支持删除电表。

### FR-03 设备树导航

- 系统应以连接 -> 电表 -> 数据分类的层级展示对象。
- 系统应支持搜索、刷新、展开、折叠。
- 选择分类节点后应刷新中部数据表。

### FR-04 数据展示

- 系统应展示 DI、数据值、单位、格式、描述。
- 系统应支持按分类展示电能量、需量、变量、事件、参数、冻结、负荷记录。

### FR-05 数据编辑

- 系统应允许用户编辑可写数据项。
- 编辑成功后应更新内存模型。
- 编辑成功后应触发持久化。

### FR-06 数据随机化与重置

- 系统应支持随机化全部数据。
- 系统应支持随机化当前选中数据列表。
- 系统应支持重置全部数据。
- 随机化后聚合数据应自动同步。

### FR-07 数据一致性

- 总电能应等于对应费率电能之和。
- 总最大需量应等于对应费率最大需量之和。
- 总功率应等于 A/B/C 相功率之和。
- 需量发生时间应符合 `yyMMddHHmm` 紧凑格式。

### FR-08 本地持久化

- 系统应使用 SQLite 保存电表数据。
- 数据库应按表地址分表保存。
- 系统读取到已有表地址时应加载历史数据。
- 系统读取到新地址时应创建初始数据并保存。

### FR-09 日志记录

- 系统应记录连接、数据编辑、随机化、数据库保存等操作。
- 成功保存数据库后应在操作日志区显示信息。

### FR-10 通信调试

- 系统应支持显示原始收发数据与协议帧。
- 系统应支持通信交互窗口查看状态。

### FR-11 数据导出

- 系统应支持导出当前数据列表到 CSV、JSON。
- 系统当前将 Excel 导出走简化兼容路径。

### FR-12 实时摘要

- 系统应在主界面显示关键实时数据摘要。
- 摘要应轮播显示 A/B/C 相相关数值。

## 4. 非功能需求

| 编号 | 需求 |
| --- | --- |
| NFR-01 | 应用应可在 Windows 环境稳定启动运行 |
| NFR-02 | UI 操作响应应保持桌面应用可接受流畅度 |
| NFR-03 | 数据库保存失败时应有错误日志 |
| NFR-04 | 数据模型应支持后续扩展更多 DI |
| NFR-05 | 代码应按模块分层，便于维护 |
| NFR-06 | 应避免引入重量级外部数据库依赖 |
| NFR-07 | 应支持 UTF-8 源码构建 |
| NFR-08 | 应具备基本输入校验能力 |
| NFR-09 | 应具备可追溯的操作日志 |

## 5. 外部接口需求

- 串口接口：基于 Qt SerialPort
- TCP 接口：基于 Qt Network
- 本地数据库：SQLite 文件 `meter_data.db`
- 文件导出：CSV、JSON

## 6. 约束

- 当前构建系统为 `qmake`
- 当前代码基线为 Qt5/C++17
- 当前项目主要面向桌面端，不含浏览器端接口

## 7. 验收基线

至少完成以下场景：

1. 创建连接并打开。
2. 新建电表并展示分类数据。
3. 修改一个数据项并重启后仍可恢复。
4. 随机化全部数据与当前数据，日志可见，数据库可恢复。
5. 打开通信调试窗口并能看到日志联动。
