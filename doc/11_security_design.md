# 安全设计文档

## 1. 安全目标

- 防止无效输入破坏模拟器稳定性
- 防止本地持久化数据损坏
- 保证通信、日志、数据库行为可追溯
- 为后续权限增强保留扩展空间

## 2. 当前安全边界

本项目当前为单机桌面工具，默认信任本机使用者，不涉及多用户账号体系。安全重点主要在：

- 输入校验
- 本地文件保护
- 数据一致性
- 错误日志留痕

## 3. 已有安全措施

### 3.1 输入校验

- 新建电表时对地址、密码、操作员代码长度进行约束
- 新建连接时对串口/TCP 参数进行校验
- 数据表数值编辑使用委托进行基础校验

### 3.2 数据库安全

- SQLite 使用参数绑定检查表是否存在
- 表名通过地址生成并做安全引用
- 序列化采用 `value_text` 与 `value_type` 双字段

### 3.3 日志与审计

- 数据保存成功写操作日志
- 数据库错误写错误日志
- 连接操作与部分关键流程写日志

## 4. 当前风险

| 风险 | 说明 |
| --- | --- |
| 明文参数 | 电表密码等参数目前作为普通文本处理 |
| 本地文件裸存 | 数据库默认位于应用目录，未加密 |
| 权限粒度缺失 | 未区分查看、编辑、写参数等角色权限 |
| 防篡改不足 | 本地数据库没有校验签名 |

## 5. 推荐增强项

- 对敏感参数增加遮罩显示与最小暴露原则
- 为数据库增加备份与恢复校验
- 对关键写操作增加二次确认
- 为参数写入引入可选密码校验策略
- 为导出文件增加操作者和时间戳元数据

## 6. 安全设计结论

当前安全设计适合单机研发和实验室场景；如后续进入更正式交付环境，建议优先补齐本地数据保护、权限控制和操作审计增强。
