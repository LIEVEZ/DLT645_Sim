# DLT645 A.1～A.6 数据标识缺口清单

## 1. 目的

本文用于对照 `DL/T 645-2007` 附录 `A.1～A.6` 与当前项目实现，整理当前尚未覆盖或仅部分覆盖的数据标识范围，作为后续逐步补全的实施依据。

## 3. 标准中的关键结论

### 3.1 费率相关不是固定 4 或 5

- 标准 A.1 当前电能类、A.2 最大需量类都支持费率 `1～63`。
- 标准 A.5 明确 `费率数 k ≤ 63`。
- 标准 A.1、A.2 结算日数据块中的费率内容，应以电表实际设置的费率数为准。
- 标准 A.6 冻结数据块也不是固定五段，冻结块长度和内容要随实际费率数变化。

### 3.2 结算日历史项范围很大

- A.1 不仅有“当前”电能量，还包含“上 1～12 结算日”版本。
- A.2 不仅有“当前”最大需量，还包含“上 1～12 结算日”版本。
- 这些历史项不只是总量，还覆盖分费率、多种无功象限、视在、分相、基波、谐波、补偿量等家族。

### 3.3 冻结类不止日冻结

- 本地标准 PDF 的 A.6 明确包含定时冻结、瞬时冻结、两套时区表切换、两套日时段表切换、整点冻结、日冻结、两套阶梯切换等多种冻结场景。
- 当前项目已扩展到多类“最新一次冻结快照”，但完整历史索引和 `050xFFNN` 组包语义仍未补齐；`0505 / 0508` 在本地 PDF 表 A.6 中未检出，先按待复核项处理。

### 3.4 单相 / 三相约束应按协议支持性处理

- 当前项目已经有单相表/三相表选择入口。
- 但标准中的很多变量项、分相项、切换冻结变量块都天然依赖相别，不能只靠界面层隐藏。

## 4. 当前实现概览

### 4.1 已有覆盖较多的部分

- `A.1` 当前电能量的一部分
- `A.2` 当前正反向有功最大需量的一部分
- `A.3` 基础变量 `0201～0207` 和少量 `0280 / 0290 / 0291`
- `A.5` 少量基础参变量
- `A.6` 多类上 1 次冻结快照

### 4.2 已知当前实现边界

- 当前 `A.1 / A.2 / A.6` 的“当前值”相关费率项已经接入 `费率数 k` 动态展开，但结算日历史家族、完整冻结体系和更多需量家族仍未覆盖。
- 单相表裁剪逻辑目前只覆盖少量 DI。
- 事件记录、冻结、扩展变量、扩展参数仍大面积缺失。

## 5. 分附录缺口清单

## 5.1 A.1 电能量数据标识编码表

### 当前已覆盖

- 当前电能家族：
  - `0000～000A`
  - `0080～0086`
  - `0015～001E`
  - `0094～009A`
  - `0029～0032`
  - `00A8～00AE`
  - `003D～0046`
  - `00BC～00C2`
- 当前值相关的费率子项和 `FF00` 数据块已统一受 `0x04000204` 控制，结构上支持 `1～63` 费率。
- 当前分相电能已补齐 `A/B/C` 三相家族，且单相表会过滤 `B/C` 相当前电能项。

### 主要缺口

- 已完成“上 1～12 结算日”电能家族接入，不再局限于“当前”。
- 已完成“上 1～12 结算日”版本下已建模系列的接入：
  - `0000～000A` 多费率总量和块
  - `0080～0086` 关联/基波/谐波/补偿量
  - `0015～001E / 0094～009A` A 相系列
  - `0029～0032 / 00A8～00AE` B 相系列
  - `003D～0046 / 00BC～00C2` C 相系列

### 结论

- A.1 当前值与“上 1～12 结算日”电能家族已经接入，且统一纳入动态费率 `k`、总量同步、树查询和随机化流程。
- A.1 当前主要缺口已经从历史结算日电能转移到更后续的扩展族校对与冻结/参数/事件等章节。

## 5.2 A.2 最大需量及发生时间数据标识编码表

### 当前已覆盖

- `0101` 当前正向有功最大需量及发生时间
- `0102` 当前反向有功最大需量及发生时间
- 当前 `0101 / 0102` 的费率子项和 `FF00` 数据块已统一受 `0x04000204` 控制，结构上支持 `1～63` 费率。

### 主要缺口

- 当前最大需量家族已补齐到：
  - `0101～010A`
  - `0115～011E / 0194～019A`
  - `0129～0132 / 01A8～01AE`
  - `013D～0146 / 01BC～01C2`
- 已完成“上 1～12 结算日”最大需量家族接入，当前值与历史值均纳入费率 `k`、总量同步、单相/三相适配和 `FF00` 数据块流程。
- 缺少标准中的“某项当前和 12 个结算日最大需量及发生时间数据块”。

### 结论

- 当前值 A.2 已从“仅支持 0101/0102”扩展为“完整最大需量族 + 动态费率块 + 单相/三相适配”。
- A.2 剩余主要缺口转为：标准中的“当前 + 12 个结算日”组合块，以及后续更高章节未实现项。

## 5.3 A.3 变量数据标识编码表

### 当前已覆盖

- `0201` 电压
- `0202` 电流
- `0203` 瞬时有功功率
- `0204` 瞬时无功功率
- `0205` 瞬时视在功率
- `0206` 功率因数
- `0207` 相角
- `02800001` 零线电流
- `02800002` 电网频率
- `02900000 / 02900100 / 02900200 / 0290FF00`
- `02910100 / 02910200 / 0291FF00`
- `23010001～23010008 / 230100FF`

### 主要缺口

- `0280` 已按当前 PDF 版 A.3 补齐到 `000B`，但项目内扩展提法中的“当前电价 / 当前费率电价 / 认证时效剩余时间”等未在该标准页明确列项，暂未扩展。
- `0290 / 0291` 当前变量组已补齐到项目现有 `CmdParse.ini` 定义的块项和配套字段，后续若要继续扩展应转入事件记录中的剩余电流历史族。
- 当前项目已补齐波形失真度、谐波含量以及标准页明确给出的温度、电池、阶梯电价变量；“当前电价 / 当前费率电价 / 认证时效”等未检出扩展项仍未覆盖。

### 结论

- 当前 A.3 已覆盖基础测量量、`0208～020B` 波形失真度与谐波含量家族、标准页明确给出的 `02800001～0280000B`，以及项目现有扩展中的 `0290 / 0291` 当前剩余电流变量块和 `2301` 端子温度块。

## 5.4 A.4 事件记录数据标识编码表

### 当前已覆盖

- `03010000～03010002`
- `03010101～0301030A`
- `03110000`
- `03110001～0311000A`
- `03120000`
- `03120101～0312060A`
- `03300000～03300600`
- `03300001～0330060A`

### 主要缺口

- `0381 / 0382 / 0383 / 0388 / 038D / 038E / 038F / 0390` 未在标准表 A.4 中检出，不再按 A.4 覆盖项统计。
- 当前仍缺少大量标准事件主族，后续需继续补齐，例如：
  - 失流、断相、电压合格率等 `0302～0310` 家族
  - 开表盖、开端钮盒、购电、电源异常、磁场干扰、报警越限等其他 A.4 事件族
  - 尚未按标准落地的其余参数表编程/清零相关扩展明细
  - 负荷开关误动作记录
  - 电源异常记录
  - 各类报警、越限及其他标准事件等
- 仍缺少大量“总次数 + 上 1～10 次详细记录”的完整结构。
- 对 `038D / 038E` 一类复合记录，当前已经落地原始码编码，但还没有完整的 `bit/bin` 语义化展示能力：
  - 发生时间 / 结束时间
  - 操作者代码
  - 前后电能值
  - 相别
  - 状态字 / 特征字 / 故障原因
- 当前 `dataItem.md` 里涉及的 `0382 / 0383 / 0388 / 038F / 0390` 只是 A.4 中与剩余电流及保护器事件最相关的一段，整个 A.4 范围仍远大于当前实现。

### 结论

- A.4 是当前缺口最大的部分之一。
- 当前已经从“只堆计数器”推进到一批可编码复合记录，后续应继续补其余事件族，并补上 `bit/bin` 复杂记录的语义化展示。

## 5.5 A.5 参变量数据标识编码表

### 当前已覆盖

- `04000000`
- `04000001`
- `04000040`
- `04000041`
- `04000101`
- `04000102`
- `04000106`
- `04000107`
- `04000201～04000206`
- `04000401`
- `04000402`
- `04000703`

### 主要缺口

- 缺少数量参数类：
  - `04000208`（待复核，当前 PDF 版 A.5 未检出）
- 缺少大量参数表和结构块：
  - `040003xx`
  - `04000403～0416` 的 ASCII / 特征字 / 额定值 / 版本号 / 资产编码 / 安装相位等
- 缺少状态字与控制字相关项：
  - `0501～0505 / 05FF`
  - `0601～0603`
  - `1001～1007 / 10FF`
- 缺少密码、整定、阈值、试跳、电压电流整定等参数块：
  - `0C01～0C03`
  - `1101～11FF`
  - `1201～12FF`
  - `1301～13FF`
  - `1401～14FF`
- 缺少仅适用于单相保护器的参数项在相别上的协议约束。

### 关键协议约束

- 标准明确：
  - 年时区数 `p ≤ 14`
  - 日时段表数 `q ≤ 8`
  - 日时段数 `m ≤ 14`
  - 费率数 `k ≤ 63`
  - 公共假日数 `n ≤ 254`

### 结论

- 当前 A.5 只覆盖了最基础的一小部分参数项。
- 参数类后续需要同时处理 `AA / AS / bit / bin` 多种格式。
- 按 `doc/DLT_645-2007_多功能电能表通信协议2010(1).pdf` 第 61 至 63 页复核后，`04000105 / 04000108 / 04000109 / 04000207` 已可按标准确认并已补入当前模型；原缺口中的 `0400010C` 实际对应的是 `04000C01~0A` 密码项，不应继续按单个 `0400010C` 处理。

## 5.6 A.6 冻结数据标识编码表

### 当前已覆盖

- 已按“最新一次冻结快照”接入：
  - `0500` 定时冻结
  - `0501` 瞬时冻结
  - `0502` 两套时区表切换冻结
  - `0503` 两套日时段表切换冻结
  - `0504` 整点冻结
  - `0506` 日冻结
  - `0507` 两套阶梯切换冻结
- 通用冻结项已覆盖 `00 / 01～08 / 09 / 0A / 10 / FF` 中的上 1 次快照主体：
  - `00` 冻结时间
  - `01～08` 正向、反向、组合无功和四象限无功电能数据
  - `09 / 0A` 正向、反向有功最大需量及发生时间数据
  - `10` 变量数据
  - `FF` 冻结数据块入口
- 冻结电能块当前已统一受 `0x04000204` 控制，并会按当前产品开放的费率数动态裁剪。

### 主要缺口

- 当前实现只覆盖上 1 次快照，尚未覆盖标准表 A.6 的完整历史序号范围：
  - `0500` 定时冻结：上 1～12 次，`DI0=01～0C`
  - `0501` 瞬时冻结：上 1～3 次，`DI0=01～03`
  - `0502` 两套时区表切换冻结：上 1～2 次，`DI0=01～02`
  - `0503` 两套日时段表切换冻结：上 1～2 次，`DI0=01～02`
  - `0504` 整点冻结：上 1～254 次，`DI0=01～FE`
  - `0506` 日冻结：上 1～62 次，`DI0=01～3E`
  - `0507` 两套阶梯切换冻结：上 1～2 次，`DI0=01～02`
- 帧解析层已补齐 `0500 / 0501 / 0502 / 0503 / 0505 / 0506 / 0507` 电能冻结块，以及 `0x0504FF01` 整点冻结块的拆分展示。
- 本地标准 PDF 的表 A.6 未检出 `0505` 与 `0508` 条目；项目现有 `0505` 分时费率切换冻结先按扩展/待复核项保留。
- 标准 A.6 中不仅冻结电能，还冻结：
  - 最大需量及发生时间
  - 切换时刻的变量数据
- 当前尚未完整实现 `050xFFNN` 全量冻结数据块的组包语义。

### 关键协议约束

- 标准 A.6 明确：冻结块中的 `n` 为“实际冻结的费率数 + 1”，其中 `1` 表示总量。
- 这意味着冻结块不能继续按“费率4、费率3、费率2、费率1、总”固定编码。

### 结论

- 当前 A.6 已从“少量日冻结”扩展到多类最新一次冻结快照，但距离标准完整历史范围和 `FF` 块语义仍有明显缺口。

## 6. 当前最关键的实现缺口

### 6.1 结构性缺口

- 目前仍以“硬编码单个 DI”方式实现，无法支撑标准里的大量家族型展开。
- 没有统一表达：
  - 历史索引
  - 费率展开
  - 数据块组装
  - 相别适用范围

### 6.2 协议性缺口

- `费率数 k` 已成为当前 `A.1 / A.2 / A.6` 家族的统一驱动源，但尚未扩展到结算日历史家族和完整冻结体系。
- 单相表/三相表的协议支持判断已开始下沉到当前变量与当前分相电能，但尚未覆盖全部附录家族。
- `AS / bit / bin` 等格式尚未建立完整读写语义。

## 7. 建议的补全优先级

### 第一优先级

- A.1 结算日电能量家族补全
- A.2 其余最大需量家族与结算日最大需量补全
- 单相 / 三相支持规则统一下沉

### 第二优先级

- A.3 扩展变量族
- A.5 参数族和格式体系扩展

### 第三优先级

- A.6 冻结体系完整化
- A.4 事件记录复合结构化

## 8. 总结

- 当前项目对 `A.1～A.6` 的覆盖并不是“差一点点”，而是以 `A.1 当前电能 + A.3 基础变量 + A.5 少量参数 + A.6 多类上 1 次冻结快照` 为主。
- 其中最先要解决的不是继续手工多加几个 DI，而是先把 `费率数 k`、历史索引、相别支持范围和数据块规则做成统一生成机制。
- 在这个基础上，再逐附录补齐标准数据族，工作量和回归风险都会明显更可控。
